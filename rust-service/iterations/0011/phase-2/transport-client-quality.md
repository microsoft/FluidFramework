## Outcome

Fixed two submission-stream lifecycle defects without protocol, service, driver, manifest, lockfile, dependency, or generated-artifact source changes. Native WebTransport now distinguishes clean EOF before a new frame from EOF within a partial frame. The browser submission stream retains each expected request ID until a complete matching response is validated and remembers terminal receive failure so EOF is observed from the underlying stream only once. Added native and real Chromium regressions for clean/partial EOF, ordered pipelining, write-side close, terminal response ordering, and one-shot EOF. Confidence is high for the exercised native/browser paths.

## Hypothesis Results

Supported. The initial native regression passed for clean EOF but failed for partial-frame EOF with `partial frame EOF was silently accepted: Elapsed(())`; after the fix, all three focused submission-stream tests passed. Fresh generated bindings and Chromium then returned `orderedSubmissionResponses: 3` and `oneShotSubmissionEof: true`. The charter hypothesis holds for these lifecycle gaps without protocol or browser API redesign.
